# macOS 27 兼容性预览 0.2.81

日期：2026-10-09。分支：`compat/macos-27`。起点：`ab04815`。

这次交付处理升级后可预见的启动与播放失败路径。当前验证机器为 Apple 芯片 Mac、macOS 15.8.1（24H32），使用 Swift 6.1.2 和 macOS SDK 15.5。没有 macOS 27 实机，也没有使用 macOS 27 SDK 编译；因此本版保留预览标记，不能视为 macOS 27 全功能验收。

## 本轮改动

| 问题 | 处理后的行为 |
| --- | --- |
| 新系统的私有 Space 接口或墙纸配置可能变化 | 先检查系统版本；未验证版本在读取私有 Space 接口和系统墙纸存储前拒绝自动过渡底图。 |
| 只读预检启动失败、超时或返回异常会阻断整个场景 | 停用本次播放的可选过渡底图，显示原因并继续动态场景。真正取消仍传播取消。 |
| 预检输出包含相似字符串也可能被当成成功 | 只有退出码为零且输出含完整确认行才允许进入底图流程。 |
| SteamCMD 启动失败一概提示 Rosetta | 区分直接和嵌套的架构错误；文件缺失、权限等错误保留普通启动提示。 |
| 快速安装没有更新版本元数据 | 安装脚本同步 `Info.plist`，关于页面与安装包版本保持一致。 |
| 场景回归向真实用户目录写入临时数据 | 注入独立的脚本存储目录，测试仅使用临时素材；应用默认目录不变。 |

版本准入仍只包含之前实际核验过的 macOS 15.8（24H23）与 15.8.1（24H32）。没有把旧墙纸结构指纹当成 macOS 27 的验证证据，也没有扩大私有配置写入权限。系统升级后的既有恢复入口不受新版本准入限制；恢复冲突仍保留账本并拒绝覆盖外部修改。

主程序、所有打包的 Mach-O 工具与渲染器均包含 arm64，当前本机 SteamCMD 同时包含 arm64 和 x86_64。当前组件无需依靠 Intel 转译来运行。Apple 的 macOS 27 发布说明提示升级后 Rosetta 不会自动恢复，因此保留对旧 Intel 组件的明确错误提示，没有执行安装 Rosetta、修改启动参数或降低系统安全设置的命令。[Apple 发布说明](https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes)

最低运行版本仍为 macOS 15.0，以符合现有打包依赖。Apple 要求 Xcode 27 运行在 macOS 26.6 或更高版本；当前主机无法提供该工具链。本轮没有加入 SDK 27 专属 API 或宣称新的系统外观已完成适配。[Xcode 系统要求](https://developer.apple.com/xcode/system-requirements/)
